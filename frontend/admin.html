📸 Create Snapshot

💡 What is a Snapshot?
A snapshot saves ALL current configuration settings (LLM, Database, Email, Scheduler, Insights, Export) at this moment. You can restore any snapshot later to quickly rollback to a known working state.

Use Cases:
  • Before production deploys
  • Before major config changes
  • To save different environment configs
  • For quick rollback if something breaks

♻️ Restore Snapshot

⚠️ Warning:
Restoring a snapshot will replace ALL current configuration with the saved snapshot state. This includes LLM, Database, Email, Scheduler, Insights, and Export settings.

Recommended: Create a new snapshot before restoring, so you can rollback if needed.

ℹ️ How to Use Semantic Layer

📖 What is Semantic Layer?

Semantic Layer adds business context on top of your raw database tables. It helps the AI understand your data better by providing:

  • Business Names: "Customer Master" instead of "cust_tbl_v2"
  • Relationships: Automatic JOIN generation between tables
  • Metrics: Pre-defined calculations everyone uses consistently
  • Dimensions: What fields to group by (region, category, etc.)

🚀 Quick Start (3 Steps)

Step 1: Create Entities

Use Auto-Discover to scan your database:

Catalog: hive
Schema: default
Tables: customers, orders, products

Click "Discover" → Review suggestions → Create entities

Step 2: Define Relationships

Connect your tables:

From: orders.customer_id
To: customers.id
Type: many_to_one

AI will automatically generate JOINs!

Step 3: Create Metrics

Define business calculations:

Name: total_revenue
SQL: SUM(orders.amount)
Format: currency

Everyone gets the same "revenue" calculation!

🤖 LLM Prompt Integration

To use semantic layer, your LLM provider's generate_sql() method needs to enhance the schema with semantic context.

📝 Required Code Changes:

In each LLM provider file (e.g., anthropic_provider.py):

        # In src/providers/llm/anthropic_provider.py

        def generate_sql(self, question: str, schema_info: str) -> Tuple[str, str]:
            """Generate SQL with semantic enhancement"""

            # ✅ ADD THIS BLOCK
            from src.core.semantic_prompt_enhancer import get_semantic_enhancer

            enhancer = get_semantic_enhancer()

            # Extract catalog/schema from schema_info
            catalog, schema_name = enhancer.extract_catalog_schema(schema_info)

            # Enhance schema with semantic context
            enhanced_schema = enhancer.enhance_schema_info(
                schema_info,
                catalog=catalog,
                schema_name=schema_name
            )

            # Get additional instructions for SQL generation
            semantic_instructions = enhancer.get_sql_generation_instructions()

            # Build prompt with enhanced schema
            prompt = f"""
            Generate SQL query from natural language.

            Available Schema:
            {enhanced_schema}

            {semantic_instructions}

            User Question: {question}

            Generate the SQL query.
            """

            # ... rest of your existing code ...

📊 Example: Before vs After

❌ Without Semantic Layer

User asks: "Show me revenue by region"

LLM sees:

Table: orders
- id, customer_id, amount

Table: customers
- id, name, region

❓ LLM confused:

  • What is "revenue"? SUM? COUNT?
  • How to join tables?
  • Which column is "region"?
✅ With Semantic Layer

User asks: "Show me revenue by region"

LLM sees:

📊 Orders (order transactions)
- Metrics: revenue = SUM(amount)

📊 Customers (customer master)
- Dimensions: region

🔗 Relationship: orders → customers
ON orders.customer_id = customers.id

✅ Perfect SQL:

SELECT customers.region,
  SUM(orders.amount) as revenue
FROM orders
LEFT JOIN customers
  ON orders.customer_id = customers.id
GROUP BY customers.region

📝 What Gets Added to LLM Prompt

When semantic layer is active, the prompt includes:

        === BUSINESS CONTEXT (Semantic Layer) ===

        📊 Available Entities (Tables with Business Names):
          • hive.default.customers
            Business Name: Customer Master
            Description: Central repository of customer information
            Dimensions: region, customer_type, segment
            Primary Key: id

          • hive.default.orders
            Business Name: Sales Transactions
            Dimensions: order_date, status
            Metrics: amount, quantity

        🔗 Available Relationships (Automatic JOINs):
          • customer_orders: orders.customer_id → customers.id (many_to_one)
          Use: LEFT JOIN customers ON orders.customer_id = customers.id

        📈 Calculated Metrics (Business Logic):
          • Total Revenue
            Description: Sum of all order amounts
            SQL: SUM(orders.amount)
            Format: currency

          • Average Order Value
            SQL: AVG(orders.amount)

        === SEMANTIC LAYER INSTRUCTIONS ===

        When joining tables:
          1. Check "Available Relationships" section
          2. Use the exact join condition specified
          3. Prefer LEFT JOIN unless specified otherwise

        When calculating metrics:
          1. Check "Calculated Metrics" section
          2. Use the exact SQL expression provided
          3. Everyone calculates metrics the same way

💡 Best Practices

✅ DO
  • Use clear, business-friendly display names
  • Document complex metrics with descriptions
  • Start with 2-3 core tables
  • Use Auto-Discover for quick setup
  • Test queries after adding relationships
  • Keep metric SQL expressions simple
❌ DON'T
  • Use technical abbreviations in display names
  • Create circular relationships
  • Define too many metrics upfront
  • Forget to set primary keys
  • Mix business logic in multiple places
  • Skip relationship descriptions

🔧 Troubleshooting

Semantic layer not enhancing queries?

Check:

  • LLM provider has semantic enhancement code added
  • Entities are defined for your catalog/schema
  • Server logs show: "Semantic layer is active and enhancing queries ✨"

Test API:

curl http://localhost:8000/api/semantic/context?catalog=hive&schema_name=default
JOINs not working automatically?

Verify:

  • Relationships are defined in "Relationships" tab
  • from_column and to_column names are correct
  • Both entities exist in the system
Metrics not being calculated correctly?

Check:

  • SQL expression is valid (test in SQL client)
  • Metric name matches what user asks for
  • Required entities are available
